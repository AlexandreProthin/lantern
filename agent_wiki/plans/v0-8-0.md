# Ground rules for every branch

- Branch from `master` as it stands when the wave starts; commit on the branch; never push, never merge.
- Run `npm ci` in `app/` first (a worktree has no `node_modules`). Browser tests take a port of their
  own: `LANTERN_PORT=<port> npx playwright test …` (the port is given per branch below).
- Gates before handing back: `npm run check` 0 errors 0 warnings, `npm test` green, the browser specs
  the branch touches green, plus new tests for new behaviour.
- Specs: amend in place with *(Amended 2026-11-17.)* or add rows with *(Added 2026-11-17.)*, as the
  wiki already does. **Do not edit `agent_wiki/log.md`**: every branch would conflict on it; the final
  report gives a log paragraph and the merge writes it.
- Strings go in `app/src/ui/strings.ts`; no hard-coded English in components.
- The user's library in `Documents/Lantern/subjects` is read-only: copy subjects into a test browser's
  storage, never write the files.
- Commit messages follow the repo's style (`area: what changed`) and end with the attribution line.

## 2. `perf/review` — port 1442

1. A focus click is a light change: no parse, validate, clone and file write of the whole subject, no
   undo step for focus alone; focus is still saved (cheaply, coalesced) so reopening keeps it.
2. The 1 s poll in `frame/persistence.ts` `refresh()` reads and hashes the whole file per open subject:
   ask Rust for the stamp (size and modified time) first and load only when it changed (or a watcher).
3. Embers (`ui/embers.ts`, the graph's ember particles) drawn on one canvas instead of SVG groups with
   drop-shadow filters; the canvas is not resized every frame.
4. The backdrop (`frame/backdrop.ts`) rests: no redraw when nothing changes, a lower rate when idle,
   colours read once per fade (not per frame), the per-mote light sum cached or on a coarse grid.
5. Streaming: Ask Amber's chat (`AskChat.svelte`, `{#key revision}`) re-renders only the turn that
   changes; Choose's Board and Rail stop recomputing `board(v)` / `missingItems(v)` on every revision
   when their inputs did not change; Learn's per-chunk `render()` is throttled to a frame.
6. Growth: existing nodes stay put when a branch grows (pin them while the new nodes seat, then
   release, or a much lower alpha for them); target under 10 % of nodes moving more than 40 px on
   *More options* on the 117-node subject (76 of 117 today).
7. Titles at low zoom: besides the focused and hovered node, the route to the focus and the module
   (depth-1) titles stay readable on a fitted map (GV-62 amended).
8. `graph-search.ts`: no `childrenOf` per node (quadratic); one children map per search.
9. `tests/graph-performance.spec.ts` measures opening (time to settle, long tasks), *More options*
   (settle time, nodes moved) and zoom, on 117 and 300 nodes, and runs by default with generous
   budgets (the strict numbers stay behind `LANTERN_PERF=1`).
10. Re-measure 117 and 300 nodes (production build, GPU) and report before/after.

## 3. `design/review` — port 1444

The user likes the overall design but it still reads as "AI generated". Fix the causes the review named:
1. Three button levels everywhere: one filled primary per view, plain text buttons for secondary
   actions, icon buttons for tools. The four identical outlined boxes under a node (*More options /
   Rewrite explanation / Add my own node / Mark as dead end*) become one primary plus quiet ones.
2. One shape per role (pills for choices and chips, one radius for buttons and fields, circles for
   graph tools); Compare's 2 px squares and mixed radii aligned.
3. One drawn icon set (the app's own SVG icons) replacing typed characters: − ⌖ + ‹ › × ▾ ▸ ✓ ≠ and
   similar, in graph tools, zoom, panels, Compare, menus.
4. Styled form controls: checkboxes, selects, radio rows, text fields in Settings and elsewhere; the
   Settings nav without boxed buttons and with one clear current item.
5. Glow only on lit things; the reading panel on a solid surface instead of glass over the backdrop.
6. The tutor's bold text is just bold, not coloured cream fragments.
7. Reading measure: the panel's text capped near 70 characters per line, and a distinct reading face
   for node content (a system serif stack or a bundled font, the licence checked).
8. The node context menu and the beige *Light it up* button brought into the same system.
Keep the identity (`agent_identity/`, the learning-node recipe in `agent_design/`) binding; screenshots
before and after for the user.

## 4. `amber/review` — port 1443

1. `companionSvg` is not rebuilt as a string ~30 times a second: build the SVG once and update the few
   moving attributes (or a cached template); no blur filter re-created per frame.
2. The bubble never covers the reading panel: placement avoids the panel (and the graph tools).
3. Reactions to the learner through the pose system: a flare when a node becomes understood, a doze
   after a long idle, a glance at new nodes, a look toward the focused node.
4. A few rare, dismissible nudges with a real role (for example "three nodes lit, none tested" in
   Learn, "two needs unanswered" in Choose), rate-limited, off with the companion's tips setting.
5. The hard-coded `'learn'` context in `companionSvg` comes from the current room.
Amend [companion](/specs/companion.md) for 2–4.

## 5. `physics/review` — port 1445 (wave 2, after 2–4 are merged)

1. Opening reveal: the settled layout appears with a short reveal (nodes fading in outward by depth,
   about half a second); none under reduced motion.
2. Collision on the label box (a node's disc plus its 150 px title), not a 62 px circle, so titles do
   not touch.
3. Cluster spacing: longer links root → modules, shorter to leaves, so modules read as groups.
4. Dragging nodes: drag moves a node and pins it; a pinned node can be released (double-click or the
   context menu); pins are kept per subject in the app-side UI state, not in the subject file
   (GV-14 amended), and *Recenter* / the tree layout ignore them.

## 6. `mobile/review` — port 1446 (wave 2)

1. Amber on a phone: hang spots and drag limits from the real header height, never under the
   two-row header, not covering the search button; tapping it works.
2. Compare on a phone: a card view per product (criteria as rows inside the card) instead of the

3. Welcome's field: the button no longer sits inside the field and cuts the placeholder.
4. Choose's rail as a phone bar shows every counter (the *pick* counter is hidden today).

3. Text size (three steps) and a light theme in Settings → Appearance, with tokens for both themes.
4. Search across all subjects (titles and node text) from Welcome or the Gallery, opening the
