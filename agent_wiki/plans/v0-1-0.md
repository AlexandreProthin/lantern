Written 2026-10-02, when the specs step closed. The contract is the 13 agreed specs in
[specs/](/specs/index.md). This plan orders the work and says when each part counts as done.
It never restates a requirement: it cites the spec. If implementation shows a spec is wrong,
the spec is changed first, through a new round of the spec workshop
(`agent_design/tool/specs_work/`), and the code follows.

# Ground rules

- **A new `app/` directory.** v0.1.0 is not the PoC with patches. The PoC (`poc/`) stays as a
  reference and a source for code to port (graph rendering, motion, panel), and is deleted
  after v0.1.0 ships. Same stack: [prism-tech-stack](/decisions/prism-tech-stack.md).
- **The core is pure and room-agnostic.** The domain model, graph operations, stats and storage
  formats live in a core that knows no room. Learn-specific prompts, actions and node kinds live
  in the Learn room module, behind the room interface of [rooms-spaces](/specs/rooms-spaces.md).
  This is the modularity requirement of [product-scope](/specs/product-scope.md) made concrete.
  A review question for every milestone: *would a Think room need to change this file?*
- **Every task cites requirement ids.** An implementation brief (for a worker agent or a
  person) names the spec ids it implements and the tests that check them. A task without ids
  is either missing from the specs or out of scope.
- **Tests come with the milestone that introduces the code**, per
  [platform-quality](/specs/platform-quality.md) PQ-20 to PQ-22. There is no test milestone at
  the end.
- **The fake tutor comes first.** The web build runs against the fake provider (IP-71), so all UI
  work and the end-to-end tests run without the CLI.

## M0: Scaffold

- `app/`: Tauri 2 + Svelte 5 + TypeScript, single-instance plugin, the Vite web build with the
  fake provider switch, a test runner for TS (unit), `cargo test` for Rust, and Playwright wired
  to the web build.
- The module layout: `core/` (pure TS), `rooms/learn/`, `frame/` (shell, spaces, theming),
  `ui/` (reusable components), Rust `storage`, `provider`, `paths`.
- The UI strings module (PQ-4).
- **Exit:** `npm test`, `cargo test` and `npx playwright test` all run green on an empty
  shell, with commands documented in `app/README.md` (PQ-23).

## M1: Core and storage

Specs: [domain-model](/specs/domain-model.md), [subject-storage](/specs/subject-storage.md).

- The `lantern/1` types, invariants (DM-50 onward) and graph operations: add, dismiss and
  restore, delete subtree, edit with `previous`, state changes with `understoodBy`.
- The generation log and derived totals; the stats definitions of
  [welcome-gallery](/specs/welcome-gallery.md) WG-30/31, in the core so every space computes
  them the same way.
- Rust storage:
  - library path and subject ids with path safety
  - atomic write and debounced save, with flush on close
  - change detection and the two conflict rules
  - format versioning and migrations
  - `state.json` and the summary cache (ST-6, ST-7)
  - Recycle Bin delete (ST-8)
- **PoC import** (ST-40 onward), tested on copies of the real files in `Documents/Lantern/subjects/`.
- **Exit:**
  - Round-trip, invariant and import tests pass.
  - The ST-50 timing (500 nodes: load < 200 ms, save < 100 ms) is measured by a test with a
    generated subject.
  - Every real PoC subject imports, and reopens identical.

## M2: Provider, protocol, context, evals

Specs: [inference-provider](/specs/inference-provider.md), [tutor-protocol](/specs/tutor-protocol.md),
[context-assembly](/specs/context-assembly.md), [platform-quality](/specs/platform-quality.md) PQ-30 onward.

- The provider contract and `ClaudeCliProvider`:
  - `--model` and `--effort`
  - the resolved model from `system/init`, and usage from `result`
  - the error taxonomy
  - cancel by killing the process tree (a Windows job object)
  - the 120 s stall timeout
  - per-call `request_id`
- Recorded stream fixtures, for success, each error type that can be provoked, and cancel. Also
  the fake provider.
- The prompts as `learn-1`: system prompt, tone lines, task templates. Then the block parser and
  the visible-text filter, and `node:` link parsing.
- Context assembly with the deterministic unit cases of CA.
- **Evals** (`evals/`, PQ-32): fixture subjects in EN and FR, small and large, plus the runner
  and the results file.
- **Exit:**
  - Fixture-based Rust tests pass.
  - Parser and context unit tests pass.
  - **`learn-1` reaches ≥ 95% on Haiku over 3 runs** (PQ-33).
  - The first measured numbers (tokens, time per task) are recorded in
    [llm-latency](/issues/llm-latency.md).

## D1: Welcome design (agent_design track)

- A `welcome` component in `agent_design/`, through its usual rounds, using the content and
  behaviour fixed by [welcome-gallery](/specs/welcome-gallery.md) (the visual is the only open
  variable; WG states the design comes from here). It can also cover the Gallery card if the user
  wants it to.
- It can start immediately.
- **Exit:** a final design with a `RECIPE.md`, like the learning node.

## M3: Frame and Study space

Specs: [rooms-spaces](/specs/rooms-spaces.md), [graph-view](/specs/graph-view.md),
[node-panel](/specs/node-panel.md), [learn-room](/specs/learn-room.md).

- **Frame:**
  - The room interface and the Learn room definition.
  - Header, subject menu (rename, tone, model, effort), the Lantern mark.
  - Space navigation and Ctrl+1/2/3; Welcome and Gallery are stubs until M4.
  - Room accent tokens, the legend, frame banners, window state.
- **Graph:**
  - Port the final learning-node design (`agent_design/learningnode/RECIPE.md`) and the PoC
    graph code.
  - Both layouts; states including self-declared and dismissed; route light; text-link lines;
    recenter and zoom.
  - The canonical keyboard table (GV-76).
  - The large-graph fallback.
  - **The spawn animation** (GV-90 to GV-97) and the busy pulse, with its constants in one
    module, tuned with the user in the running app.
- **Panel:**
  - All node states.
  - Editing with `previous` and compare/revert.
  - The selection popover.
  - Markdown with KaTeX, Mermaid, highlighting and sanitization.
  - Streaming display, error cards, the delete dialog, per-node drafts.
- **Learn actions**: every row of the LR action tables, the state machine, one generation per
  subject (LR-40, IP-50), pending check.
- **Exit:**
  - Playwright covers the main loop against the fake tutor (PQ-22), including dismiss and restore,
    edit, cancel, and restart persistence.
  - The real CLI works end to end on a new subject.
  - 500 nodes pan and zoom smoothly (GV performance requirement).
  - The user has tried the spawn animation and accepted its tuning.

## M5: Settings and first run

Spec: [settings](/specs/settings.md).

- Every setting in the SE table, applied on change.
- The library folder change flow.
- Provider status, with *Check again* and *Test*, plus the step-by-step **instructions** for a
  missing or signed-out CLI ([cli-signin-instructions-only](/decisions/cli-signin-instructions-only.md)).

- **Exit:** AC-6 and AC-7 pass by hand on a machine where the CLI is first missing, then

## M6: Release

- The installer: Prism's unsigned per-user NSIS, with the updater plugin and
  `createUpdaterArtifacts` wired but no update flow (PQ-40 onward).
- A final eval run on the shipped prompt version.
- **Acceptance**: AC-1 to AC-7 of [product-scope](/specs/product-scope.md), each walked through
  by hand on the installed build. AC-2 needs real days: **a dogfooding week** where the user
  learns one real subject across several days on the installed build. Issues found there are
  fixed, or recorded as issues for v0.1.x.
- Tag `v0.1.0` and write a GitHub release with the installer. The PoC directory is removed in
  the same release.
- **Exit:** the acceptance walk-through and the dogfooding week are done, and the user says ship.

# Risks to retire early

| Risk | Where it bites | Retire it in |
|---|---|---|
| CLI error output differs from what IP assumes (the exact strings are unknown until recorded) | error UX, settings status | M2: record real fixtures first, adjust IP's detection table |
| Killing the CLI's process tree on Windows leaves children | cancel, AC-5 | M2: a job-object test with a real call |
| Haiku does not reach 95% on `learn-1` | the eval bar | M2: iterate the prompt; if stuck, discuss the bar, not silently lower it |
| Mermaid and KaTeX weight or render cost in a streaming panel | panel smoothness | M3: render only on stream end, or debounced |
| Physics layout with placeholders as bodies jitters | spawn feel | M3: tune with the user; tree layout is the fallback |
| `node:` links to wrong ids from the model | text-link lines | M2 evals check it; M3 renders unknown ids as plain text |

# Not in v0.1.0

The Later list of [product-scope](/specs/product-scope.md) holds; the main items are merge,
regenerate, parallel generation, other providers, the sign-in button, search, export, undo,
the Think room, auto-update UI and i18n. A request for one of these during v0.1.0 goes to the
spec workshop as a scope change, not into a milestone.
