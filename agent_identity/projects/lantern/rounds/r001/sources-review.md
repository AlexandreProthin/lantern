# Lecture du contexte — 2026-10-04
Documents copiés sous sources/ ; les chemins ci-dessous sont relatifs au dépôt original.

- README.md, Why/Rooms : espace de travail avec une IA pour apprendre, réfléchir,
  explorer et décider ; graphe d'idées persistant ; l'utilisateur fait le travail.
- product-scope.md, Purpose : usage quotidien de l'auteur, Learn pour v0.1.0,
  architecture prévue pour plusieurs rooms. Aucun marché démographique précis établi.
- tutor-protocol.md, TP-10 : tons adaptés à plusieurs niveaux de familiarité ; cela
  soutient une identité accueillante, sans définir une cible enfant ni un public unique.
- product-scope.md PS-7/PS-40–42 et rooms-spaces.md RS-30–33 : Learn ambre, cadre
  sombre, calme chaleureux, accents par room ; cadre partagé. Ce sont des contraintes
  d'intégration actuelles, pas une décision sur la palette définitive du compagnon.
- platform-quality.md PQ-1 : Windows pour la version actuelle. Le favicon reste demandé
  par l'utilisateur, même si le produit actuel est une application de bureau.
- graph-view.md GV-100–103 : mouvement réduit et équivalents statiques des états ;
  ne pas faire dépendre l'information du mouvement.
- README et architecture/lantern-overview.md comportent des paragraphes d'avancement
  anciens (PoC seul / implémentation en cours) malgré la mention de sortie v0.1.0.
  Retenir la vision produit ; privilégier les spécifications stables pour les contraintes.
- settings.md présente system/on/off alors que GV-100 exclut « never reduce » : détail
  de réglage contradictoire, sans effet sur notre exigence d'une variante statique.
  Ne pas arbitrer ni modifier ces spécifications dans le travail d'identité.

Points à ne pas confondre : « chaque room a sa propre lanterne/accent » ne décide pas
si le compagnon change d'identité. La demande actuelle est un compagnon à travers les
rooms ; degré de variation à clarifier. RS-33 limite les animations du cadre actuel :
l'intégration future du compagnon devra préciser son emplacement et ses déclencheurs.
« En accord avec l'esprit de l'app » n'impose ni n'interdit une représentation littérale.
